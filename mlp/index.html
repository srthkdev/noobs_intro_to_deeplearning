Understand the final MLP project

Updated 15 November 2026 · Your L1 feedback, L2 preparation, model concepts and practice. Actual project notebook code is private; the evidence map links to Kaggle.

One listing is one example. The inputs describe its location, capacity, facilities, operator and review history. The target is one of four price tiers. This is supervised multiclass classification.

How the actual workflow fits together

EDA + features24,000 fit-only CV rowsThree shared group foldsFull fitting: 195,842 rowsCompare on 27,978 validation rowsSelect initial or tuned candidateAudit: 55,926 rowsRefit all 279,746 labels114,538 test predictions

CV tests hyperparameter settings within fitting data. Each fold learns its own feature vocabulary, caps, imputers, scalers and categories. The shared CV sample makes the search affordable on CPU. Then the selected settings are fitted on the full fitting partition and compared with the initial settings on the same validation rows. The winner is the best validation candidate. Its audit results are checked afterwards.

CV boosting budgets are fixed at 600 LightGBM rounds and 400 CatBoost rounds. During full fitting, validation early stopping chooses rounds within limits of 2,000 and 1,200. Structural settings and stopping rounds are therefore selected at separate, explicit stages.

What each model learns

SGD logistic classifier

Learns weighted combinations of the engineered and one-hot encoded features. SGD updates the weights to reduce logistic loss. Multiclass classification uses one-versus-rest. Scaling helps its optimisation and regularisation.

alpha controls regularisation. We tested 0.00001, 0.0001 and 0.001.

Extra Trees

Fits many independently randomised trees, then averages their class probabilities. It can learn nonlinear relationships and interactions. This run uses 80 trees, random feature subsets and bootstrap=False.

We tested depth/leaf-size pairs 16/10, 20/5 and 24/5.

LightGBM

Adds gradient-boosted trees sequentially to improve the current multiclass loss. It uses fitted native categorical levels and numerical features, rather than the baseline one-hot matrix.

We tested leaf-count/minimum-support pairs 31/100, 63/50 and 63/100. Full fitting uses learning rate 0.04 and validation early stopping.

CatBoost

Also uses gradient-boosted trees, with built-in categorical processing. Its input branch supplies category strings and a fixed marker for missing numerical values.

We tested depth/L2 pairs 6/5, 7/5 and 7/10. Full fitting uses learning rate 0.06 and validation early stopping.

Hinge, log loss and how learning happens

Loss versus metric

A loss provides a training penalty. A metric judges predictions. Our SGD classifier trains with log loss; candidate selection uses macro F1. Macro F1 is not the differentiable objective used for its gradient updates.

What is hinge loss?

Hinge loss wants correct predictions with a sufficient margin from the decision boundary.

Binary formula: L = max(0, 1 − y f(x)), with y ∈ {−1,+1}. f(x) is a decision score, not a probability; y f(x) is the signed margin.

Margin −0.5 → loss 1.5 (wrong side). Margin 0.4 → loss 0.6 (correct side, too close). Margin 1.2 → loss 0 (sufficient margin). A linear SVM combines a margin objective with regularisation.

What is log loss, and why did we use it?

Log loss penalises low probability assigned to the correct answer; we chose it for a logistic baseline with probability outputs.

Binary formula: L = −[y log(p) + (1−y) log(1−p)], with y ∈ {0,1}. For y=1, this is −log(p): p=0.9 gives ≈0.105; p=0.1 gives ≈2.303. Confident wrong predictions receive a large penalty.

SGDClassifier(loss="log_loss") learns logistic one-versus-rest classifiers. With loss="hinge", it behaves as a linear SVM and has no direct predict_proba output. We did not compare hinge experimentally, so we cannot claim log loss scored better. The multiclass boosting objective is instead commonly written −(1/N) Σᵢ log pᵢ,true-class.

What is a gradient and an optimiser?

A gradient describes how a loss changes with the parameters; an optimiser uses it to update them.

Basic gradient update: w ← w − η∇L(w). η is the learning rate. Gradient descent uses the full-data gradient; stochastic methods use individual examples or smaller batches. Our SGD linear baseline updates coefficients. Tree boosting fits successive trees using loss-gradient information; it is not the same training algorithm as SGD on a linear coefficient vector.

How does a tree decide a split?

A split divides the data into groups that make class predictions more informative.

For class proportions pₖ in a node, Gini = 1 − Σ pₖ². A pure node has Gini 0. With two equally represented classes, Gini is 0.5. Compare weighted child impurity against parent impurity. Extra Trees uses random threshold candidates and the default Gini criterion. Boosted trees use their objective’s gradient-based split gains, so do not describe all models as minimising Gini.

Explain our early stopping

We stopped adding boosting stages after validation macro F1 had not improved for 100 rounds and kept the best iteration.

Full LightGBM fitting allowed 2,000 rounds. The winning run’s best iteration was 1,508. Patience 100 does not mean training ends at round 100. After selecting the winner, the all-labelled-data refit used a fixed 1,508 rounds because there was no longer a separate validation partition for early stopping.

Training macro F1 ≈0.9443 versus validation ≈0.7355 indicates a generalisation gap. Early stopping, regularisation and leaf controls help constrain fitting; they do not eliminate all overfitting. We did not produce a learning-curve experiment in this final notebook.

Preprocessing, pipelines and CV in simple terms

What did we engineer?

We made relationships easier to use: capacity ratios, combined ages, date intervals, log counts and facility indicators.

Example: years×12 + months provides total age; date subtraction gives an interval; parsed common facility labels become multi-hot flags. Log1p compresses long tails. Fitted term caps and a facility vocabulary are learned inside the pipeline. A basic-versus-engineered SGD comparison improved CV macro F1 from ≈0.570655 to ≈0.575330. That is a combined-representation result, not proof that each individual feature helped.

Which scaler and encoder did we use?

SGD and Extra Trees use StandardScaler on imputed numerical columns and OneHotEncoder on categorical columns.

z = (x − fitting mean) / fitting standard deviation. Mean 10, standard deviation 2, x=14 → z=2. Scaling does not make a skewed distribution normal. Numerical missing values use median imputation with indicators.

One-hot encoding gives categories separate indicator columns, avoiding an invented numeric order. Our settings include min_frequency=20 and handle_unknown="ignore". Rare fitting categories are grouped; unseen levels produce all-zero category blocks with this unknown setting. A facility list uses multi-hot flags because several facilities can be present at once.

LightGBM instead uses numerical NaNs and fitted pandas categorical levels. CatBoost receives category strings and numerical −999 markers. These two branches use neither StandardScaler nor the baseline one-hot representation.

What are Pipeline and ColumnTransformer?

Pipeline connects sequential stages; ColumnTransformer applies different preprocessing to different columns.

ListingFeatures → representation → model. In the encoded branch, numbers go through median filling/scaling and categories through one-hot encoding; the outputs are joined. fit learns state; transform applies it; predict transforms and predicts. clone copies settings into an unfitted estimator, not learned weights.

model__num_leaves means the num_leaves parameter of the pipeline step named model. Cloning whole pipelines during CV makes each fold learn its own preprocessing from its training rows.

What exactly was our CV and tuning?

Three grouped folds repeatedly hold out different parts of a fitting-only sample; GridSearchCV averages each setting’s macro F1.

Our partitions contain 195,842 fit, 27,978 validation and 55,926 audit rows. A 24,000-row sample from fit supplies shared stratified group-aware folds. If A is held out, fit on B+C; rotate through B and C. Duplicate raw profiles stay together. The unit is a raw-profile group, not an operator or a metro.

Four models × three configurations × three folds = 36 tuning fits. The feature ablation adds three basic-representation CV fits. The full validation partition later compares initial and selected candidates and chooses early-stopping rounds. Audit evaluation follows selection, but this audit had been inspected before and is a reused holdout.

Grid search evaluates specified candidates; randomized search samples candidates. The executed tree/boosting searches use paired configurations. Full 2×2 Cartesian practice is labelled separately. Tuning can reduce full validation performance: CV estimates are uncertain and based on a smaller training sample.

ConceptAnswer to understand
Linear regression / MSEPredict a continuous value as wᵀx+b. MSE = (1/N)Σ(y−ŷ)²; squared errors penalise large deviations.
R²1 − Σ(y−ŷ)² / Σ(y−ȳ)². It compares regression errors against predicting the evaluation-set mean; it can be negative. It is not our classification metric.
Logistic functionσ(z)=1/(1+e^(−z)); maps a real decision score into a binary-class probability.

Correlation / causationCorrelation measures association, commonly linear association for Pearson r. Association alone cannot establish a causal effect.

5. Why scale, and how does StandardScaler work?

Scaling keeps large-unit numeric features from dominating SGD updates and regularisation.

StandardScaler learns each fitting mean and standard deviation, then applies z = (x − mean) / standard deviation to numeric inputs after imputation. It does not make a skewed distribution normal. Extra Trees shares this encoded branch for convenience; threshold trees usually do not need scaling. Native boosting branches do not use this scaler.

6. Why one-hot encoding or native categories?

Nominal labels have no meaningful numeric distance, so I avoid treating their arbitrary codes as quantities.

SGD/Extra Trees use OneHotEncoder with min_frequency=20 and handle_unknown="ignore". Rare training levels share an infrequent category; unseen levels are ignored under this setting. LightGBM receives pandas categorical columns whose levels are fitted on training rows; unknown levels become NaN. CatBoost receives strings with an explicit missing category.

9. What is a pipeline, and how does this code work?

A pipeline packages feature creation, representation and prediction into one reproducible estimator.

fit learns caps/vocabulary, imputers/category levels, and model parameters. transform applies learned rules without relearning them; predict transforms new rows and returns labels. GridSearchCV clones the whole pipeline inside every fold. Full fitting reuses a representation learned only on Xf. Final refitting relearns it on all labelled rows after model selection; that refit has no independent local score.

Evidence: Custom fit and transform (cell 13) · Pipeline construction (cell 14) · Fold refits (cell 18) · Full-data refit (cell 30)

10. Why compare these four models?

I compare a linear baseline, randomised trees, and two boosting implementations.

SGD logistic regression tests a scalable linear boundary with log loss. Extra Trees averages randomised trees to capture interactions. LightGBM adds trees sequentially to reduce a multiclass objective. CatBoost supplies another categorical boosting approach. All initial and selected candidates use the same full fitting and validation rows; this makes their validation comparison meaningful.

Rows are true tiers, columns predicted tiers; the diagonal contains correct predictions.

Macro F1 averages the four tier F1 scores equally; accuracy counts all correct rows equally. Row-normalised diagonal entries are recalls. A good accuracy can conceal a weak tier, which is why I select on macro F1.

What is the difference between facility tokens and text words?

A facility token is one complete parsed list item, even if its name contains several words.

parse_facilities reads JSON/Python-style lists safely, strips and deduplicates items, and returns malformed flags. The final model learns common complete facility labels; it does not run TF-IDF on free text. For a general text question, word tokenisation splits text into units, bag-of-words counts them, and TF-IDF downweights widely occurring terms. That is a concept explanation, not an experiment in this notebook.

Evidence: Facility parser and fitted vocabulary (cell 13)

Where did feature selection and SVD fit in?

They belong to the earlier milestone study, not the final nonlinear pipeline.

Earlier M3 used 80,000 fitting / 20,000 validation rows. Its uncompressed representation scored 0.6554; ANOVA selecting 200 inputs scored 0.6427; L1 selection of 200 scored 0.6591. Truncated SVD combined sparse inputs into 80 components, retained 71.4% variance and scored 0.5715. Selection retains original inputs; reduction builds combinations. Several earlier fits hit iteration limits. The final pipeline retains its engineered representation and has no L1/ANOVA/SVD selection stage; these earlier numbers must not be mixed with final model gains.

What mathematics and optimisation should I explain?

Training minimises a loss; evaluation asks how well unseen predictions solve the task.

For a true-class probability p, multiclass log loss contributes −log(p): confident wrong predictions are penalised heavily. SGD updates weights in a negative estimated-gradient direction with regularisation controlled by alpha. Extra Trees averages randomised trees; boosting adds trees that improve an objective. Learning rate controls step size, depth/leaves control capacity, leaf support discourages tiny partitions, and L2 penalises large leaf values. Macro F1 is the selection metric here, not a differentiable loss directly optimised by SGD. Early stopping monitors validation F1.
